# 酒店点评回复智能体 · v2

把顾客点评按 **好评 / 中评 / 差评** 三级分类，从 **服务 / 位置 / 设施 / 卫生** 四个维度逐一诊断，生成可直接发布到 OTA 平台的回复。

两种形态：

- 🖥 **离线网页工具** `index.html` —— 打开即用，支持单条精修 + 批量出稿 + 导出 CSV，可部署给全店共享；
- 🤖 **智能体提示词** `system-prompt.md` / `agent-config.json` —— 接入任意大模型、Dify、Coze 做自动化。

## 二、快速开始

### 1. 本地使用

双击 `index.html` 用浏览器打开。填酒店名、选评分、粘贴点评 → 自动识别四维度 → 一键出稿。

> **双击 `index.html` 没反应？** 说明系统里 `.html` 的默认打开程序指向了一个已卸载的浏览器（最常见是卸了 Chrome 之后）。
> 两种解决办法：① 双击 `打开工具.command`（推荐，会自动选已安装的浏览器）；
> ② 右键 `index.html` → 打开方式 → Safari → 勾选「始终以此方式打开」。详见 `sharing.md` 第九节。

### 2. 共享给同事（内网，推荐）

```bash
cd hotel-review-agent
chmod +x serve.sh && ./serve.sh          # 默认 8899 端口
```

终端会打印 `http://192.168.x.x:8899/`，发到门店群即可，同事和手机无需安装任何东西。
详见 `sharing.md`（也支持 GitHub Pages / Vercel / Nginx 部署）。

### 3. 全店话术统一

店长在「⚙️ 门店配置」填好酒店名、电话、落款、禁用词 → **导出 JSON** → 同事**导入 JSON**，一键对齐。配置里不含任何客人数据，可放心在群里传。

### 4. 接入大模型 / 智能体平台

把 `system-prompt.md` 的「一、系统提示词」放进 System Prompt，用户输入模板做成表单变量；或直接读取 `agent-config.json` 集成。推荐 temperature 0.5~0.7（差评 ≤0.4），知识库挂载 `templates.md` + 门店真实信息。

## 四、设计逻辑

### 4.1 三级分级（优先级：严重问题 > 评分 > 情感倾向）

| 等级 | 触发条件 | 回复目标 | 建议字数 |
| --- | --- | --- | --- |
| 好评 | 4~5 分，或文本以肯定为主（允许 1 处轻微遗憾） | 让顾客被看见，沉淀复购与口碑 | 80~200 |
| 中评 | 3 分，或褒贬参半、以建议为主 | 化解遗憾、给确定性改进承诺、争取二次机会 | 120~300 |
| 差评 | 1~2 分，或情绪以抱怨为主 | 先救情绪 → 给方案 → 把沟通移到私下 | 200~420 |

**严重问题清单**（强制走升级流程，禁止套模板）：食品安全/异物、虫鼠害、人身与消防安全、财物丢失损坏、隐私泄露、员工辱骂冲突、涉法涉诉、媒体曝光。

### 4.2 四维度识别

| 维度 | 覆盖内容 | 词库示例 |
| --- | --- | --- |
| 服务 | 前台接待、入住退房效率、员工态度、响应速度、行李/叫醒/送餐、早餐、押金发票 | 热情、耐心、态度差、爱答不理、没人接、办入住太慢 |
| 位置 | 交通、地铁车站机场、周边商圈、景区可达性、导航难度、停车 | 交通便利、出门就是、太偏、不好找、打车难、停车紧张 |
| 设施 | 房型面积、床品、隔音、空调热水、网络、电梯、装修新旧 | 隔音差、空调不制冷、热水忽冷忽热、WiFi 连不上、老旧 |
| 卫生 | 布草、卫生间、水渍霉斑、灰尘毛发、异味、虫害、杯具 | 头发、污渍、霉味、烟味、蟑螂、毛巾有点旧 |

**三段式判定**（避免"提到名词就算好评"）：

```
出现负向证据                                   → 差评
无负向 + 出现强评价词（热情/干净/方便/舒服…）   → 好评
仅出现中性名词（前台/地铁/空调/毛巾…）          → 中性提及
完全未提及                                      → 未提及（不写进回复，不编造）
```

另带**否定语境守卫**：`房间不大`、`床不舒服`、`交通不方便` 不会被误判成好评。

### 4.3 回复五段结构

```
① 称呼 + 致谢   ② 情感回应（共鸣/共情）   ③ 具体回应（按维度复述原话）
④ 行动 / 邀约（改进承诺或补偿）          ⑤ 结尾 + 落款「XX酒店 管理团队 敬上」
```

### 4.4 合规红线（工具会自动检查）

| 类型 | 禁止表述 |
| --- | --- |
| 泄露隐私 | 房号、客人全名、手机号 |
| 诱导好评 | "五星好评""好评返现""加微信发红包"（平台违规） |
| 削弱认可 | "但是""不过""您误会了" |
| 绝对化承诺 | "绝对不会再发生""100% 保证" |
| 争辩甩锅 | "其他客人都没反映""是您使用不当" |
| 涉法涉诉 | 公开认定责任、讨论赔偿金额、引用法律条文 |

## 五、批量处理用法

```
5|前台热情，房间干净，位置方便，下次还来
3|空调不太制冷，隔音一般，毛巾有点旧
1|卫生间有蟑螂，床单有污渍，前台没人接电话
```

- 支持 `5|` `5,` `5：` `5、` 等分隔；不写评分则用页面上的「默认评分」；
- 也支持**空行分段**（一条点评占一段，可含换行）；
- 等级判定可选「按文本自动判定（更严格）」或「按评分判定」；
- 生成后每条都能单独改评分/等级/回复，**导出以编辑后的结果为准**；
- CSV 列：序号、评分、等级、点评原文、识别维度、建议回复、待确认项。

## 七、可扩展方向

1. **接入 OTA 接口**：自动拉取未回复点评 → 调模型出稿 → 人工审核队列 → 一键发布；
2. **整改台账联动**：每条差评自动生成「责任部门 / 动作 / 时限」，下次回复时能说"已完成整改"；
3. **门店知识库**：把房型、设施、周边交通、可用补偿项喂给模型，杜绝编造；
4. **数据看板**：按四维度统计差评分布，定位最该投入的改进项（如"设施-隔音"连续 3 周高发）；
5. **多语言回复**：面向 Booking / Agoda 的外语点评，同一套结构输出英文回复。

---

## 八、使用提醒

- 工具生成的是**草稿**，不是终稿：好回复的关键是复述顾客说过的具体内容，请人工确认细节真实；
- 差评回复里的"已整改"必须真的已做或已排期，否则二次投诉风险更高；
- 严重问题请勿使用模板话术，交由店长/法务线下处理；
- 点评原文只在本机浏览器内处理，工具不联网、不上传、无埋点。
